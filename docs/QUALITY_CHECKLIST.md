# 质量验收清单

按变更范围选择适用项。勾选不是目的，必须保存实际命令结果和人工验收结论。

## 1. 通用检查

- [ ] 已运行 `git status --short --branch`，未覆盖用户修改。
- [ ] diff 只包含本任务范围，无调试日志、临时数据和生成报告。
- [ ] `git diff --check` 无空白错误。
- [ ] 未提交 `.env`、token、Cookie、密钥、用户隐私或构建产物。
- [ ] README、路线图、计数或操作说明与代码一致。

## 2. 自动化验证矩阵

| 变更类型 | 必须执行 | 视情况执行 |
| --- | --- | --- |
| 仅 Markdown 文档 | `git diff --check` | 检查链接、命令与路径 |
| 课程/Meta 内容 | `npm run typecheck`、`npm run test`、`npm run build` | 课程页/练习页浏览器抽查 |
| Runner/Step/解析器 | 上述三项 | 对应 E2E、完整 `npm run test:e2e` |
| UI/样式/响应式 | 上述三项、相关 E2E | 完整 E2E、截图对比 |
| 路由/store/i18n | 上述三项、相关 E2E | localStorage 兼容/刷新直达 |
| Worker/Pyodide | 上述三项、生产 smoke | 真实线上 Python 执行 |
| Workflow/部署 | 本地 build | 推送后所有 Actions job、线上冒烟 |

最终报告记录通过数量、失败数量、跳过原因和运行环境。只写“测试通过”不够。

## 3. 课程内容检查

- [ ] id 唯一，language/chapterId 与 `lessonChapters` 一致。
- [ ] prerequisites 全部存在且无明显环。
- [ ] 注册顺序与课程导航顺序一致。
- [ ] 概念从动机到规则再到边界，未堆砌术语。
- [ ] C++、C#、Python 示例完整；输出注释实际正确。
- [ ] 版本相关语法已注明版本。
- [ ] comparison 讲语义差异，不只做关键字替换。
- [ ] 至少 2 个常见错误，包含原因与修法。
- [ ] 练习可独立理解，提示递进，答案覆盖要求。
- [ ] 课程树、详情、练习页、进度页都能找到或记录该课。
- [ ] 英文 UI 不泄漏未翻译中文；未完成双语化时诚实提示。

## 4. 算法与可视化检查

- [ ] Runner 纯函数、确定性，无随机/时间/DOM/网络依赖。
- [ ] 每一步是独立快照；修改某步不会污染其他步。
- [ ] `stepId` 连续，统计累计单调。
- [ ] 四份代码的 `codeLineId` 集合一致。
- [ ] 默认、preset、空/最小规模、失败路径和特有边界都验证。
- [ ] 有 aux 的案例使用正确 aux，而不是只改变案例标题。
- [ ] 复杂度描述与当前实现一致。
- [ ] 错误输入显示明确 invalid 状态与可理解说明。
- [ ] 切换语言不改变步骤序列，当前代码行仍正确。
- [ ] 前进、后退、播放、暂停、重置、跳首尾均正确。
- [ ] 可视化、变量、指针、调用栈、输出与本步说明同步。

## 5. 跨端 UI 检查

至少检查以下宽度：

- [ ] 320px：最低支持宽度。
- [ ] 390px：典型手机。
- [ ] 768px：竖屏平板。
- [ ] 1024px：大平板/小桌面。
- [ ] 1440px：宽桌面。

每个适用页面检查：

- [ ] body 无横向滚动；代码/表格仅在自己的容器内滚动。
- [ ] 导航可打开、关闭、跳转，遮罩和层级正确。
- [ ] 主要 CTA 不被粘性导航、底栏或安全区遮挡。
- [ ] 触控目标至少 44px，标签和筛选不会过度拥挤。
- [ ] 文本无异常截断，中文标题换行自然。
- [ ] 深色与浅色对比、边框和状态色都可辨识。
- [ ] 中英文切换后没有溢出、残缺文案或语言泄漏。
- [ ] 减少动态效果时仍能理解状态变化。

## 6. 可访问性检查

- [ ] 跳到主内容链接有效。
- [ ] Tab 顺序符合视觉顺序；所有交互有可见焦点。
- [ ] 图标按钮有可理解的 accessible name。
- [ ] Modal/抽屉有焦点陷阱、Escape 关闭与焦点恢复。
- [ ] `aria-expanded`、`aria-controls`、tab roles 与真实状态一致。
- [ ] 不使用错误 role 包裹仍需交互的子元素。
- [ ] 成功、错误、进行中不只用颜色表达。
- [ ] 动态结果需要时通过合适的 live region 宣告，但不制造重复播报。

## 7. 在线实验室检查

- [ ] Python Worker 只在需要时加载。
- [ ] 首次加载、运行中、成功、语法错误、运行时错误、超时、重试都有明确状态。
- [ ] Python 输出真实来自 Pyodide，不使用静态假结果。
- [ ] C++/C# 清楚标注演示模式，没有“已编译运行”的误导。
- [ ] Worker 错误后可重建，页面不会永久卡死。
- [ ] 生产子路径下 Worker 与动态模块 URL 正确。

## 8. 部署验收

- [ ] `npm run build` 本地成功并生成 `dist/404.html`。
- [ ] push 使用普通 `git push`，未 force push。
- [ ] GitHub Actions `build` 成功。
- [ ] GitHub Actions `deploy` 成功。
- [ ] GitHub Actions `production-smoke` 成功。
- [ ] 线上首页、一个课程、一个算法和 `/lab` 可访问。
- [ ] 线上 Python 可实际运行并产生预期输出。
- [ ] 刷新子路由不返回不可用 404。

## 9. 交付报告

- [ ] 用用户能理解的语言先说明结果。
- [ ] 列出关键改动和关键文件。
- [ ] 列出实际验证命令与结果。
- [ ] 说明未解决限制和风险；没有则写“无已知阻断项”。
- [ ] 如已提交/推送，给出 commit、分支、Actions 和线上链接。
